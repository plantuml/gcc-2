# Draft for GCC Bugzilla (component: tree-optimization)

**Summary:** [15 Regression] -foptimize-crc: code after a call is removed and replaced by
`__builtin_unreachable ()` when a loop fills a CRC32 table (wrong code at -O2)

GCC 15.2.0 (Ubuntu 15.2.0-16ubuntu1), x86_64. `gcc -O2 -c repro/crc_v3.c` (or the smaller
crc_v4.c .. crc_v6.c when they reproduce). The loop is the classic generation of a CRC32 table (bit
reflected, polynomial 0xEDB88320). With `-O2` the final tree of the function is:

    allocateArray (&Arr_I_Cls, 256);
    __builtin_unreachable ();

Everything after the call is gone (25 lines instead of 102). `-fno-optimize-crc` or `-fno-tree-vrp`
or `-O1` give correct code. GCC 13 and 14 are correct. The dump of the pass (`-fdump-tree-crc-details`)
shows that the pass finds the CRC ("Bit reversed", "Polynomial's value is ...").

Found with the C generated by TeaVM 0.16.0 (a program that crashed at start-up); the whole story is
in https://github.com/plantuml/gcc-2.

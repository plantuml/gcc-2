# Draft for GCC Bugzilla (component: tree-optimization)

**Summary:** [15 Regression] -foptimize-crc: the code after a call is replaced by
`__builtin_unreachable ()` when a loop computes a CRC32 table (wrong code at -O2)

**Version:** GCC 15.2.0 (Ubuntu 15.2.0-16ubuntu1), x86_64-linux-gnu, Ubuntu 26.04. GCC 13.3 and 14.3 are correct.

**Test case** (`repro/crc_v4.c`, 25 lines): the table of a CRC32 (bit-reflected, polynomial 0xEDB88320)
is filled in an array that comes from a function the compiler cannot see. The loops have the shape
generated by TeaVM (`while (1)`, `goto`).

    gcc -O2 -c crc_v4.c -fdump-tree-optimized

**Actual result:** the function is reduced to the call, followed by `__builtin_unreachable ()` (12
lines of final tree, no `ret` in the code). All that follows the call to `allocate` has been removed:

    allocate (256);
    __builtin_unreachable ();

**Expected:** the call returns, the table is filled, the function returns.

**Options:** `-fno-optimize-crc` (new in GCC 15), `-fno-tree-vrp` and `-O1` give correct code
(67 / 67 / 73 lines). `-fdump-tree-crc-details` shows that the pass finds the CRC ("Bit reversed",
"Polynomial's value is ...") and stops after "Checking 5 bit.".

The same loops written without goto (`crc_v5.c`, `crc_v6.c`) are transformed by the pass too (29-32 lines
instead of 65-68) but the code stays correct.

**Found with:** the C generated by TeaVM 0.16.0 for java.util.zip.CRC32, whose static initializer was
cut after the call that allocates the table (the program crashes at start-up). Complete history, CI
logs and the 177 generated files: https://github.com/plantuml/gcc-2
